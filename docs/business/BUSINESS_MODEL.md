# BUSINESS MODEL — Wenits.fun
Status: Draft v0.1 | Date: 2026-11-01
No revenue invented. No token price/APY.

## 1. Value proposition
- For scanners: fastest Solana hype read (moon score + candles).
- For degens: zero-ruin paper trading + weekly status.
- For creator: X-follower growth via gated arena.
- For future sponsors: seasonal competitions with budget-capped pools.

## 2. Customer segments
Retail crypto, memecoin traders, active traders, Web3 gamers, DeFi users, casual explorers. Different entries: radar (no login), arena (trade), X gate (social).

## 3. Revenue hypotheses (to validate, not committed)
- H1 Sponsored competitions: sponsor funds fixed pool, Wenits takes ops fee. Requires: budget custody, eligibility, anti-Sybil. Not built.
- H2 Premium features: advanced analytics, private tournaments. Requires: paywall + wallet. Not built.
- H3 Protocol affiliate/integration rev-share (swap routing). Requires: DeFi integration. Not built.
- H4 API/data access for hype signals. Requires: reliability SLA. Not built.
Explicitly excluded now: token sale, yield on deposits, wagering rake.

## 4. Cost structure
Infra: Postgres, Redis, hosting web/API, GeckoTerminal/DexScreener rate limits (free tier now), X API v2 usage, OpenRouter inference (scraper off by default). Ops: settlement compute, moderation, audits for future financial features.

## 5. Key metrics
Activation: radar → first trade. Retention: weekly board return. Integrity: duplicate/stale rates. Cost: API calls/trade, cache hit rate.

## 6. Sustainability rule
Every reward needs funding source + budget + distribution + eligibility + anti-abuse before launch. Points ≠ liability. Virtual balances separate from on-chain assets. No new-user deposits as reward source.

## 7. Current reality
No monetization implemented. No reward pools. No treasury. Virtual $10,000 has zero redemption value.
